PROBLEM STATEMENT & MOTIVATION 02 / 10

The Fallacy of Client-Side Web Proctoring

Why traditional browser exam security fails against modern AI-assisted automation.

❌ The Weakness in Current Systems

  • Superficial Obfuscation: Disabling right-click or copy-paste is easily bypassed by external scripts.
  • Selenium/Puppeteer Trap: Traditional bots get detected instantly via navigator.webdriver flags.
  • Binary Telemetry Gaps: Portals rely on simple focus events without validating physical mouse trajectories or typing dynamics.

🎯 Our Research Objective

  • Build a Hardened Defense (Blue Team): Create a zero-tolerance monitoring suite with biometric cadence checks and signed JWT payloads.
  • Engineer a Stealth Auditor (Red Team): Develop an autonomous, screen-aware agent using Chrome DevTools Protocol (CDP) to evaluate defensive boundaries.

BLUE TEAM DEFENSE SUITE 04 / 10

Zero-Tolerance Defense Mechanisms

Multi-layered client-side telemetry and cryptographic session enforcement.

Focus & Visibility

window.blur and visibilitychange listeners terminate the session immediately if tab focus is lost.

Fullscreen Lock

Enforces HTML5 fullscreen. Any exit event disables question inputs and invalidates the session token.

Cadence Timing

Calculates Inter-Keystroke Intervals (IKIs). Rejects text if keydown delta is < 15ms (programmatic paste).

Signed Tokens

Backend signs question IDs with HMAC SHA-256 tokens. Prevents tampering with answers or grading key.
